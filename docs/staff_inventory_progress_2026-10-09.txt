1. 프로젝트 구성
- 직원 앱: apps/staff_app
- Flutter 패키지 이름: shoepick_staff_app
- Android 표시 이름: shoepick_staff_app
- lib/main.dart는 앱 실행, model/은 데이터·JSON, view/는 화면, vm/은 조회·업무 처리 코드로 구성했다.
- 기존 StatefulWidget 기반 화면 상태 처리를 유지하고 있다. 전체 GetX 전환은 하지 않았다.
- backend/main.py는 FastAPI 실행·라우터 등록·공통 오류 처리를 담당한다.
- backend/database.py는 .env의 설정으로 PyMySQL 연결을 생성한다.
- backend/dependencies.py는 요청별 DB 연결 제공·예외 시 rollback·종료 시 close를 처리한다.
- backend/features/에는 inventory.py, purchase_requisitions.py, purchase_approvals.py,
  manufacturer_orders.py, goods_receipts.py, dashboard.py를 구성했다.
- DB 비밀번호는 로컬 backend/.env에 보관한다. 저장소에는 .env.example만 포함한다.

2. 본사 재고 조회 — 구현 완료
- API: GET /api/v1/inventory/headquarters
- headquarters_inventory, product_variants, products를 연결한다.
- 상품명·코드·색상·사이즈와 실물·예약·불량·가용 수량을 반환한다.
- 가용 수량은 기존 DB 생성 컬럼을 사용한다.
- 상품 검색, 옵션 ID 필터, 허용 목록 기반 정렬, 페이지 처리를 제공한다.
- 성공 응답은 data와 pagination이며, 결과가 없으면 빈 목록을 반환한다.
- 실제 DB에서 본사 재고 242건과 상품 코드 검색을 확인했다.
- Flutter 본사 재고 화면에 실제 API 조회·검색·정렬·페이지 이동·오류 안내를 연결했다.

3. 대리점 보관 현황 조회 — 구현 완료
- API: GET /api/v1/inventory/branches/{branch_id}
- pickup_holdings를 기준으로 branches, fulfillment_items, fulfillments, order_items, orders를 연결한다.
- 상품 정보는 주문 당시 order_items 스냅샷을 사용한다.
- 상품·옵션·수량·보관 상태·주문/출고 번호·입고/수령 시각을 반환한다.
- 상태 필터, 상품 검색, 옵션 ID 필터, 정렬, 페이지 처리를 제공한다.
- 상태를 지정하지 않으면 입고 대기·수령 완료를 포함한 전체 기록을 조회한다.
- READY_FOR_PICKUP을 지정하면 고객 수령 대기 상품만 조회한다.
- total_count는 SKU 종류 수가 아니라 보관 기록 수다. 전체 이력의 수량 합계는 현재 재고가 아니다.
- 없는 대리점은 HTTP 404 / NOT_FOUND, 기록이 없는 대리점은 HTTP 200 / data:[]를 반환한다.
- Flutter 대리점 직원의 현재 재고와 대리점장의 대리점 보관 현황 화면에 실제 API를 연결했다.
- 기본 상태는 고객 수령 대기다. 전체 이력·입고 대기·검수·수령 완료 등으로 변경할 수 있다.
- 지점 변경 시 이전 비동기 응답이 새 지점 화면을 덮어쓰지 않도록 처리했다.
- API에 과거 날짜 기준 조회가 없어 기존 날짜 선택 화면을 현재 보관 현황 조회로 수정했다.

4. 대리점 ID 불일치 수정 — 완료
- 기존 목업은 구 이름의 나열 순서로 ID를 생성하여 강남점=1, 성동점=16을 사용했다.
- 실제 MySQL branches는 강남점=2, 성동점=1이다.
- district_code별 실제 ID 매핑으로 수정하고 25개 대리점 모두 실제 DB와 대조했다.
- 로그인 지점 선택·목업 주문·관련 테스트의 ID도 맞췄다.
- 강남점은 /branches/2, 성동점은 /branches/1로 호출한다.
- 검증 시 두 지점의 고객 수령 대기 기록은 각각 3건이었다.
- 로그인 이름과 실제 API 경로가 일치하는 회귀 테스트를 추가했다.
- 현재 로그인은 목업이므로 ID 매핑은 확인한 DB 기준의 명시적 설정이다.
  정식 인증 연결 후에는 직원의 실제 소속 지점 정보를 사용해야 한다.

5. 주문 재고 확보·해제 — 공용 함수 구현 완료
- 위치: backend/features/inventory.py
- reserve_order_inventory(db, order_id=..., expires_at=...)
- release_order_inventory(db, order_id=..., reason=...)
- 주문 담당이 동일한 DB 연결·트랜잭션에서 호출하는 함수다. 외부 POST API는 아직 없다.
- 확보는 DB 주문 품목 수량을 기준으로 예약 수량을 증가시킨다.
- 해제는 RESERVED 예약을 해제하고 예약 수량을 감소시킨다. 실물 수량은 유지한다.
- inventory_reservations와 inventory_movements를 함께 저장한다.
- 같은 주문의 재시도는 추가 증감·이력을 만들지 않고 changed=False를 반환한다.
- 기존 예약의 만료 시각을 연장하지 않고, 처리된 예약을 다시 확보하지 않는다.
- 신규 예약은 미래의 만료 시각이 필요하다. DB와 같은 시간 기준의 naive datetime을 전달한다.
- 확보 호출은 출고 전 PENDING_PAYMENT/PAID/PREPARING 상태를 허용한다.
- 해제 호출은 PENDING_PAYMENT/CANCELED 상태를 허용한다.
  결제 완료 주문 취소는 주문 담당이 취소 상태를 반영한 뒤 같은 연결로 호출한다.
- 실제 출고 이력이나 CONSUMED 예약이 있으면 일반 해제를 막는다.
- 재고 부족·주문 품목과 예약 불일치·예약 수량 부족을 검사한다.
- 주문·예약·SKU 잠금과 고정된 SKU 잠금 순서를 적용했다.
- 오류 시 savepoint로 함수 내부 변경을 복구한다.
- 함수는 commit하지 않는다. 전체 업무 성공 후 호출자가 commit, 실패 시 전체 rollback을 수행한다.
- /docs에는 본사·대리점 조회 API만 표시된다. 확보·해제는 공용 Python 함수이므로 표시되지 않는다.

6. Android 에뮬레이터 환경 — 반영 완료
- 기본 API 주소: http://10.0.2.2:8000
- PC의 FastAPI는 127.0.0.1:8000에서 실행한다. MySQL 주소는 기존 환경 설정을 유지한다.
- API_BASE_URL은 dart-define으로 재정의할 수 있다.
- Android INTERNET 권한과 debug 빌드의 HTTP 허용 설정을 적용했다.
- 브라우저용 CORS 미들웨어와 추가했던 웹 실행 폴더를 제거했다.
- Pixel Tablet / emulator-5554에서 APK 설치·실행을 확인했다.
- 최근 대리점 ID 수정본도 에뮬레이터에 재설치·실행했다.

7. 검증 결과
- Flutter: dart format lib test, flutter analyze 오류 없음, flutter test 12개 통과.
- Android: debug APK 빌드 성공 및 에뮬레이터 설치·실행 확인.
- Backend: python -m pytest backend/tests 30개 통과.
- 실제 HTTP 조회와 Dart API 코드로 본사·대리점 데이터 조회를 확인했다.
- MySQL 일시적 테스트 테이블에서 확보·중복 재시도·부족 재고·해제·savepoint·외부 rollback을 확인했다.
- 일시적 테이블 검증은 실제 업무 테이블의 데이터 변경 없이 수행했다.
- 동시 요청 보호를 위한 잠금은 구현했으며, 다중 세션 동시 부하 테스트는 아직 수행하지 않았다.
- TestClient 관련 라이브러리 deprecation 경고는 있지만 테스트는 통과했다.

- 담당 B의 Firebase 인증·직원 권한·소속 대리점 검증 연결.

- 기존 DB·API 이름을 유지하고 담당자 간 데이터 계약을 확인하며 진행한다.

9. 실행 방법
프로젝트 루트:
  python -m pip install -r backend/requirements.txt
  python -m uvicorn backend.main:app --reload

직원 앱 폴더 apps/staff_app:
  flutter pub get
  flutter run -d emulator-5554

목업 바로 보기 후 직책과 대리점을 선택하여 재고 화면을 확인한다.
에뮬레이터 ID가 다르면 flutter devices에 표시된 ID를 사용한다.
