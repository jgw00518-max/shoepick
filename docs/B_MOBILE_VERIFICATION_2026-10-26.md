# 최신 통합본 실제 휴대전화 검증 — 2026-10-26

## 실행 출처

- 소스: `shoepick_b_auth_integration`, 브랜치 `feature/b-auth-integration`.
- 서버: 통합본 `backend.main:app`, `127.0.0.1:5556`.
- 고객·직원 앱: 각각 통합 폴더에서 빌드·설치·실행.
- 앱 설정: `API_BASE_URL=http://127.0.0.1:5556`.
- USB Android: ADB `reverse tcp:5556 tcp:5556` 확인.
- 구버전 5555 서버와 구분했다. 8000의 기존 프로세스는 사용하지 않았다.

실제 앱이 고객/직원 세션 API에 보낸 Bearer 토큰을 임시 검증 서버의 메모리에서만
재사용하여 동일 서버에 GET 요청을 보냈다. Firebase·DB 의존성을 대체하지 않았다.
토큰·비밀번호·비밀키는 출력하거나 파일에 저장하지 않았다.
프로젝트 인증·업무 소스는 이번 검증에서 변경하지 않았다. 임시 검증 도구는 OS 임시 폴더에서 실행했다.

| 직원 토큰 | GET `/api/v1/inventory/headquarters` | 200 |

| 잘못된 토큰 | 고객·직원 세션 | 각각 401 |

직원 세션에는 역할 7개·권한 3개·소속 지점 5개가 반환됐다.
데이터가 없는 목록의 200은 조회와 인증 성공을 뜻하며 실제 주문/재고가 존재한다는 뜻은 아니다.

## 검증하지 못한 사항

| 검사 | 이유 |
|---|---|
| 실제 본인 주문 상세 200 | 해당 고객의 주문 데이터 없음 |
| 실제 다른 고객 주문 상세 차단 | 비교할 다른 고객 주문 데이터 없음 |
| 존재하지만 미배정된 지점 차단 | 테스트 직원이 현재 존재하는 활성 지점 5개에 모두 소속 |
| 권한이 부족한 별도 실제 직원 | 현재 테스트 계정은 기존 조회 권한을 모두 보유 |
| 주문 생성·결제·취소·출고 실행·재고 변경 | 실제 데이터 변경 금지 조건에 따라 미실행 |
| 품의·결재 실제 실행 | 현재 DB에 관련 팀 코드가 요구하는 권한이 없고 데이터 변경 작업임 |

소유권·권한 없음·타 지점 차단의 Mock 자동 테스트 결과와 위 실제 검사 결과는 구분한다.
실제 검증 데이터가 없다는 이유로 주문·계정·지점을 생성하지 않았다.
이번 검사에서 503 응답은 관찰하지 않았지만, 호출하지 않은 API까지 검증된 것은 아니다.

2. 품의 작성·상신·결재 권한은 팀의 DB 환경·배정표와 현재 DB의 차이를 확인.
3. 최종 변경 검토 후 사용자의 별도 승인으로 커밋·푸시 진행.
